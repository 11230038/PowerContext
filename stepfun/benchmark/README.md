# 可复现质量与性能测试

`corpus/` 是可直接导入应用的小型中文验收语料，`queries.json` 同时给出相关来源文件。它适合验证链路；正式提交建议扩充至 500～1000 个 chunk 和至少 30～50 个查询。

## 操作

1. 清除浏览器该站点缓存，记录冷启动模型加载。
2. 新建知识库，导入 `corpus/*.md`，保存 UI 显示的向量化、写入和刷新耗时。
3. 逐条执行 `queries.json`，记录返回来源和三段查询耗时。
4. 热启动后重复查询至少 10 次，统计 median 与 P95。
5. 将 Worker 的 dtype 临时改为 `fp32`，新建独立知识库并重新导入，作为同后端质量基线。
6. 计算 Recall@5；按相关来源二值 relevance 计算 nDCG@10。

结果 JSON 放入 `results/`，目录默认忽略生成文件，建议提交经过确认的汇总表和必要的原始日志。

## 指标

```text
Recall@5 = 命中的相关来源数 / 全部相关来源数
DCG@10 = Σ rel_i / log2(i + 1)
nDCG@10 = DCG@10 / 理想排序的 DCG@10
```

比较 FP32 与 INT8 时必须保持浏览器、设备、后端、批大小、切块、seekdb 配置及候选数量一致。
